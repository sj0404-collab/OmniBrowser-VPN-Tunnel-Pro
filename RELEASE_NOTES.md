**OmniBrowser VPN Tunnel Pro 4.2.4**

По журналу и скриншотам 4.2.3.

**Чёрное окно PiP**
- Раскладка «видео на всё окно» применялась ко **всем** `<video>` на странице; скрытые превью-видео (YouTube/Rutube держат несколько) ложились поверх играющего чёрным прямоугольником. Теперь растягивается только одно — играющее (или самое крупное), выбор обновляется каждые 2 с.
- При входе в PiP из HTML5-полного экрана видео возвращается на страницу (отдельная полноэкранная поверхность в окне PiP рисуется чёрным).
- После смены размера окна WebView принудительно перекладывается и раскладка повторяется (0,3 / 0,9 / 1,8 с); если видео встало на паузу — возобновляется.
- В журнал пишется строка `[PiP] окно …, WebView …, страница: {…}` с размерами и состоянием видео — по ней видно причину, если окно всё же пустое.

**Туннель приложений: серверы «умирали» один за другим**
- «Read timed out» при CONNECT означало не смерть сервера Browsec, а то, что **адресат** (Telegram DC, порт 5222, серверы Browsec из расширения в Lemur) не ответил серверу за 5 с. Мы же отправляли сервер «вниз» на 3 минуты — за минуту так выбывали все (lt9 → lv86 → lt40 → lt14 → de73 → lv211 → lv197), и Telegram оставался без картинок и видео.
- Теперь при таком таймауте сервер проверяется быстрым CONNECT к Google: жив — остаётся в работе (с небольшим штрафом), только мёртвый уходит на 3 минуты. На CONNECT приложениям даётся 9 с вместо 5.
- Сервер пропускается из-за очереди только при ≥4 одновременных попытках (было 2) — меньше бесполезного разброса по серверам при старте Telegram.
- Замер качества не запускается дважды параллельно; неизмеренные серверы подписываются «не измерен», а не «0 мс».

Подпись — единый ключ, ставится поверх 4.x.
