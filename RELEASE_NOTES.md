**OmniBrowser VPN Tunnel Pro 4.3.3**

**YouTube: «нет pot», хотя видео играло (журнал 14:44)**
Мобильный плеер YouTube теперь качает видео по протоколу SABR: один POST-запрос на `/videoplayback`, а PO-token лежит **в теле запроса** (protobuf), а не в адресе — поэтому сниффер его не видел. Теперь:
- перехватчик fetch/XHR разбирает тело SABR-запроса (protobuf: `streamer_context` → `po_token`) и достаёт PO-token и расшифрованный `n` прямо из запроса плеера — в журнале `[Видео] PO-token плеера перехвачен из SABR-запроса`; они подставляются в адреса всех качеств из ответа плеера;
- по актуальному списку yt-dlp (10.2026) ANDROID_VR и IOS уже требуют PO-token для всех форматов; клиент по умолчанию без токена — **VISIONOS**. Он добавлен первым в InnerTube-путь (через закреплённый сервер), ANDROID_VR оставлен запасным;
- при 403 на адреса плеера загрузчик сам переключается на InnerTube VISIONOS через закреплённый сервер и продолжает с того же байта.

**4.3.2**

**YouTube: 403 после 4.3.1 (журнал 14:05) — сменён способ получения ссылок**
По актуальной таблице yt-dlp клиент IOS теперь требует PO-token для прямых ссылок (отсюда 403 даже через закреплённый сервер), а ANDROID_VR с IP VPN-сервера упирается в «Sign in to confirm you're not a bot». Теперь три пути по порядку:
- **A (основной):** адреса из ответа плеера страницы + `pot` (PO-token) и уже расшифрованный параметр `n`, подсмотренные в запросах самого плеера к googlevideo (они одинаковы для всех форматов ролика). Загрузка идёт тем же путём, что и страница. Для этого **видео должно быть запущено** хотя бы на секунду — иначе плеер ещё не делал запросов и pot взять неоткуда (шторка об этом напомнит);
- **B:** InnerTube ANDROID_VR через закреплённый сервер (когда pot недоступен);
- **C:** InnerTube IOS → **HLS-манифест** (HLS у iOS-клиента pot не требует) через закреплённый сервер: качества как варианты HLS, сборка сегментов в файл.
Сниффер теперь запоминает и SABR-запросы плеера (без itag) — именно из них берутся pot/n.

**4.3.1**

**Исправление: YouTube отвечал 403 на загрузку (журнал 12:21)**
Причина: адреса googlevideo привязаны к IP, с которого получен ответ плеера, а прокси браузера выбирает сервер Browsec «гонкой» для каждого соединения — IP менялся, и YouTube отклонял запрос. Теперь для YouTube:
- список форматов берётся запросом к InnerTube (клиенты ANDROID_VR / IOS, без PO-token и без шифрования подписей) через **один закреплённый сервер Browsec**, и все соединения загрузки идут строго через него (новый `ExtensionProxy.openPinnedTunnel`, собственный HTTP-клиент поверх туннеля);
- если сервер упал или YouTube всё же ответил 403/410 — автоматически запрашиваются свежие адреса для тех же itag через другой сервер, и загрузка продолжается с того же места (до 3 переездов);
- журнал: `YouTube: форматы получены через клиент ANDROID_VR (N), сервер lt40…`, `YouTube: адреса обновлены, сервер …`.

**4.3.0**

**Новое: загрузка видео и музыки из плеера любого сайта**
Когда на странице появляется видео или аудио (плеер начал запрашивать медиа), справа внизу над страницей появляется плавающая кнопка ⬇. Нажатие открывает шторку с вариантами:
- **Видео** — список качеств (2160p / 1440p / 1080p / 720p / 480p / 360p …) с размером файла. Для YouTube раздельные дорожки видео и звука скачиваются и **склеиваются в один MP4 без перекодирования** (MediaMuxer), поэтому доступны все качества, а не только 360p/720p;
- **Только звук** — M4A (AAC) или Opus «как музыка», плюс дополнительные языки озвучки, если они есть;
- для **HLS-потоков (m3u8)** — выбор качества, сборка сегментов в один файл, поддержка шифрования AES-128;
- для прямых файлов (mp4/webm/mov/mp3…) — сам файл и «только аудио из видео» (извлечение дорожки без перекодирования).

Откуда берутся ссылки: встроенный перехватчик fetch/XHR/ресурсов страницы (в том числе во встроенных плеерах-iframe), элементы `<video>/<audio>`, ответ плеера YouTube (`movie_player.getPlayerResponse`), а если YouTube спрятал адреса (SABR) — запасной запрос к InnerTube (ANDROID_VR / IOS) без расшифровки подписей. DRM-потоки (Netflix и т.п.) скачать нельзя.

Загрузки идут **через тот же маршрут Browsec, что и страница** (локальный прокси браузера), в фоновом сервисе с уведомлением: процент, скорость, кнопка «Отмена». Докачка кусками по 8 МБ при обрывах. Файлы попадают в `Movies/OmniBrowser` (видео) и `Music/OmniBrowser` (аудио) и сразу видны в галерее и музыкальных плеерах; по нажатию на готовое уведомление открываются. Журнал: строки `[Загрузка]`.
