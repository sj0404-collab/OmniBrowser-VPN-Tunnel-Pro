**OmniBrowser VPN Tunnel Pro 4.2.2**

По журналу 4.2.1: приложения ходили через «первый доступный» сервер Browsec (lt40 → lt9 → de73), часть серверов отвечала с таймаутами, картинка 500 КБ грузилась 2 минуты; в браузере YouTube при первом открытии показывал чёрный плеер и начинал играть только после перезагрузки.

**Туннель приложений выбирает самый быстрый сервер, а не первый попавшийся**
- Для каждого сервера измеряются **реальное время CONNECT** (при каждом соединении приложений и активной проверкой каждые 5 минут — параллельный CONNECT www.google.com:443 через 10 лучших по пингу серверов) и **фактическая скорость отдачи** (КБ/с, по секундам с данными). Из них считается оценка: задержка + штраф за скорость ниже 400 КБ/с.
- Страна профиля приложения / страна расширения учитывается, только если её лучший сервер не хуже общего лучшего больше чем в 1,5 раза — иначе берётся самый быстрый из всех. Больше не «тянет» на медленные de58/de73 из-за профиля DE.
- Текущий сервер удерживается, пока другой не лучше его хотя бы на 30 % — без прыжков lt9 → lt40 → de73.
- Не ответивший при замере сервер выключается на 3 минуты заранее, а не после того, как на нём зависли соединения Telegram/Lemur.
- В журнале: «лучшие серверы Browsec: lt40 180 мс · 950 КБ/с, …» и «приложения идут через сервер Browsec … (CONNECT N мс)».

**Браузер: чёрный плеер YouTube при первом открытии**
- Сразу после загрузки PAC расширения проверяются первые 4 сервера маршрута YouTube/Google; мёртвые помечаются «вниз» до первой страницы, поэтому запрос плеера не ждёт их таймауты.

**Почему приложение YouTube не видно в журнале**
- В журнал попадают только приложения из списка VPN; остальные ходят напрямую, минуя туннель. На этой сети YouTube-приложение не блокируется, поэтому оно работает и так. Чтобы оно шло через Browsec (и появилось в журнале), добавьте его в список приложений VPN.

Подпись — единый ключ, ставится поверх 4.x.
