**OmniBrowser VPN Tunnel Pro 4.1.1**

По журналу с устройства (21:56–22:00): userspace-стек 4.1.0 работает — соединения приложений доходят до обработчика с верными адресами. Сломаны были маршруты, не туннель.

**Браузер: `ERR_PROXY_CONNECTION_FAILED` на YouTube**
- Причина — таймаут Chromium на CONNECT (~10 с): локальный прокси перебирал серверы расширения по очереди (6 с + 8 с на каждый), два зависших греческих сервера Browsec = 16 с ожидания.
- Теперь ступенчатая гонка: серверы расширения (до двух параллельно) → через 2,5 с рабочие серверы автотуннеля Browsec → через 5 с встроенный обход DPI; общий предел 8,5 с, первый ответивший побеждает. Таймауты на сервер: 4 с + 5 с.
- Отказ прокси по порту (403/405) больше не считается «сервер упал».

**Приложения шли «обход DPI», хотя туннель Browsec включён**
- Учётные данные Browsec и список его серверов теперь сохраняются и переживают «Отключить» прокси расширения и перезапуск: туннель приложений работает независимо от того, управляет ли расширение прокси браузера. Одни учётные данные применяются ко всем серверам Browsec без повторных запросов к расширению.
- Через туннель идут **все** TCP-порты приложений (Telegram: 443, 5222, по IP без SNI), а не только 443/80.

**DNS приложений отравлен (`www.google.com → 194.221.250.50`, прямые соединения к Telegram висят)**
- A-запросы приложений резолвятся DoH-запросом к dns.google **внутри туннеля Browsec** (кэш по TTL), затем — обычный DoH, затем UDP. Провайдерский фильтр больше не подсовывает свои IP.
